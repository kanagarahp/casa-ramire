## 1. Login lintas perangkat

### Arsitektur

- Akun disimpan di tabel Postgres **`casa_users`**.
- Password memakai **scrypt**. Hash lama SHA-256 dari browser masih diterima,
  lalu otomatis di-upgrade saat login pertama.
- Login menghasilkan **token HMAC 30 hari**.
- Endpoint terproteksi menerima:
  - `Authorization: Bearer <token>` (perangkat yang login), atau
  - `x-admin-key` (kompatibilitas perangkat lama/pemulihan).
- Token memuat fingerprint password (`pv`). Ganti password atau nonaktifkan
  akun → token lama langsung ditolak.

### Endpoint

Semua ditangani satu serverless function:

```text
POST   /api/auth/login
GET    /api/auth/users
POST   /api/auth/users
PATCH  /api/auth/users
DELETE /api/auth/users?id=...
POST   /api/auth/change-password
POST   /api/auth/bootstrap
POST   /api/auth/recover
POST   /api/auth/forgot-password
POST   /api/auth/reset-password
```

File:

- `api/auth/[...action].js` — router catch-all
- `api/_lib/auth-handlers.js` — implementasi handler
- `api/_lib/auth.js` — scrypt, user helper, token
- `api/_lib/token.js` — HMAC, expiry, password fingerprint
- `api/_lib/db.js` — tabel `casa_users`
- `src/services/auth.js` — login/logout, token storage, user management UI
- `src/services/sync.js` — sinkronisasi pakai token, fallback kunci admin

### Migrasi satu kali

Perangkat utama owner (yang punya Kunci admin) harus dibuka sekali setelah
deploy. Aplikasi otomatis memanggil `/api/auth/bootstrap`, menyiapkan akun
server, dan menampilkan toast:

`Akun server disiapkan (...). Perangkat lain sekarang bisa login.`

Perangkat lain cukup login username/password. Kunci admin **tidak perlu** diisi
lagi.

### Perilaku penting

- Perangkat baru selalu **menarik state server dulu**; tidak bisa menimpa data
  dengan state kosong.
- Marker `casa-ramire:sync` menyimpan versi server terakhir per perangkat.
- Logout menghapus token lokal.
- Akun nonaktif / password berubah → perangkat lain diminta login ulang.
- `meta.updatedBy` menyimpan editor terakhir dan ditampilkan di dashboard.

### Batasan yang disengaja

- Akun/password sekarang **terpusat di server**; bukan lagi per perangkat.
- Kunci admin tetap disimpan lokal di perangkat utama dan tidak ikut state.
- Booking pembayaran belum punya invoice PDF (lihat backlog).

## 2. Invoice PDF + email

### Generator PDF

- `api/_lib/invoice.js` — normalisasi invoice + render PDF (`pdf-lib`)
- `api/invoice.js` — endpoint PDF dan kirim email
- `api/_lib/state-store.js` — baca `casa_state` dari Postgres
- `src/services/invoice.js` — preview HTML, download, cetak, kirim email
- `src/ui/invoice-logo.js` — mark logo untuk preview

Endpoint:

```text
GET  /api/invoice?type=bill|invoice|pos&id=...   # unduh PDF
POST /api/invoice                                # kirim PDF + email
     { type, id, mode: "billing"|"paid"|"reminder", to? }
```

Desain PDF:

- Header hijau tua `#1f3938`
- Logo rumah emas `#c99a4a` + 4 daun putih + wordmark `CASA RAMIRE` serif emas
- Bagian **Klien**: Nama, Alamat, Telepon
- Tabel **Items / Total**, periode sewa
- Bar **Total** hijau tua
- Footer **Tanggal** dan **No Order**
- Badge **LUNAS** / **BELUM DIBAYAR**
- Info rekening + jatuh tempo untuk invoice belum dibayar

Logo vector saat ini adalah rekonstruksi dari gambar yang dikirim owner. File
logo asli (SVG/PNG) belum ada di repo. Jika nanti tersedia, ganti path di
`src/ui/invoice-logo.js` dan `BRAND_PATHS` di `api/_lib/invoice.js`.

### Preview & tombol invoice

Tombol **Invoice / Tampilkan Invoice** tersedia di:

- Dashboard → tagihan aktif dan menunggak
- Sewa & Verifikasi Kas → tagihan sewa
- Financial → Invoice Manual
- POS → Riwayat dan struk POS
- Detail Penghuni → Riwayat Pembayaran

Preview menyediakan:

- **Download PDF**
- **Cetak** (membuka PDF di tab baru)
- **Kirim Email** (email penerima bisa diedit)

Invoice manual: setelah dibuat, preview langsung terbuka; email dikirim dari
preview (tidak auto-send saat create).

### Email otomatis

- **Tagihan/invoice belum dibayar** — PDF terlampir, teks tagihan + rekening.
- **Pengingat H-3** — cron harian mengirim untuk tagihan/invoice belum dibayar
  yang jatuh tempo atau periode sewanya berakhir 3 hari lagi; PDF terlampir.
- **Ucapan terima kasih** — otomatis setelah owner klik **Verifikasi** pada
  tagihan sewa, invoice manual, atau invoice POS. PDF + ucapan terima kasih.
- **POS lunas di kasir** — email otomatis jika email pelanggan dicentang.
- Salinan email dikirim ke inbox admin (`NOTIFICATION_EMAIL`).

Draft teks email lengkap: `docs/INVOICE-EMAIL-DRAFTS.md`.

### File email

- `src/services/billing-notify.js` — kirim tagihan/invoice via endpoint PDF
- `src/services/email.js` — email umum/booking
- `api/_lib/email.js` — Resend + attachment
- `api/email/send.js` — endpoint email + cek status (GET, butuh key full-access)
- `src/services/reminders.js` — pengingat lokal/manual H-3
- `api/cron/billing-reminders.js` — cron H-3 + PDF

## 3. Catatan troubleshooting email

Saat sesi ini, dua email uji dikirim ke `casaramirejogja@gmail.com`:

- Invoice + PDF: `01a20d36-f495-77c3-b9a5-51b8f68295ae`
- Email biasa: `01a20d3a-2763-7039-8ed9-835fca12fbc7`

Resend menerima keduanya (HTTP 200), tetapi API key yang terpasang hanya
punya izin **kirim** (`This API key is restricted to only send emails`), jadi
status akhir tidak bisa dibaca lewat API.

Jika email tidak masuk lagi:

1. Cek Inbox, Spam, Promotions, All Mail, cari `Casa Ramire`.
2. Cek dashboard Resend → Emails dengan ID di atas (Delivered/Bounced).
3. Pastikan `EMAIL_FROM` memakai domain yang sudah verified di Resend.
4. Pastikan `NOTIFICATION_EMAIL` / email properti benar.
5. Jika perlu status otomatis, buat API key Resend full-access dan simpan di
   environment server. Endpoint `GET /api/email/send?id=...` akan mengembalikan
   status Resend.

## 4. Environment variables

```text
RESEND_API_KEY                             # email transaksional

EMAIL_REPLY_TO                             # opsional
NOTIFICATION_EMAIL                         # inbox admin
CRON_SECRET                                # opsional untuk cron
DOKU_*                                     # opsional
```

Mengganti `AUTH_TOKEN_SECRET` atau `CATALOG_ADMIN_KEY` membatalkan token login
yang ada. Jangan commit nilai asli.

## 6. Batasan & backlog berikutnya

- **Booking invoice** — pembayaran booking belum punya invoice PDF/terima kasih
  otomatis. Bisa ditambahkan tipe `booking` di normalizer + tombol di detail
  booking.
- **Auto-renewal H-3** — pengingat H-3 saat ini untuk tagihan/invoice **belum
  dibayar**. Jika tagihan periode berjalan sudah lunas, belum ada invoice
  perpanjangan otomatis. Perlu keputusan bisnis apakah sistem membuat tagihan
  perpanjangan H-3.
- **Logo asli** — masih vector rekonstruksi. Ganti dengan file asli jika ada.
- **Resend status** — API key masih send-only; status email belum bisa dibaca
  otomatis.
- **Bulk actions** — belum ada kirim invoice massal / download ZIP.
- **Audit log lengkap** — baru `meta.updatedBy` (editor terakhir), belum log
  aktivitas per record.
- **Fungsi Vercel** — total saat ini 11 dari batas 12 (Hobby). Tambahan
  endpoint baru harus digabung ke catch-all atau menghapus yang tidak dipakai.

## 8. Rollback

Kode lama masih bisa memakai `x-admin-key`; tabel `casa_users` tidak
mengganggu. Jika perlu rollback frontend, sinkronisasi perangkat utama tetap
berjalan dengan Kunci admin.
