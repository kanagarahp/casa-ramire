# Handoff 24 November 2026 — Login lintas perangkat

## Tujuan

Pengguna ingin membuka Casa Ramire di laptop, HP, atau tablet dan langsung
melihat data yang sama setelah login — tanpa mengisi **Kunci admin** di setiap
perangkat.

Sebelum perubahan ini:

- Data operasional disimpan di `localStorage` perangkat dan disinkronkan ke
  `/api/state` hanya jika Kunci admin diisi di perangkat tersebut.
- Akun dan password disimpan per perangkat.
- Perangkat baru menampilkan data kosong/seed meskipun login owner berhasil.

## Perubahan utama

### 1. Akun terpusat di server

Tabel baru `casa_users`:

- `id`, `username`, `name`, `role`, `active`
- `password_hash` (scrypt; hash lama SHA-256 dari browser masih diterima lalu
  otomatis di-upgrade saat login pertama)
- `created_at`, `updated_at`

Endpoint baru:

```text
POST   /api/auth/login              # username/password -> token 30 hari
GET    /api/auth/users              # direktori akun (butuh login)
POST   /api/auth/users              # tambah akun (owner)
PATCH  /api/auth/users              # ubah nama/role/status/password (owner)
DELETE /api/auth/users?id=...       # hapus akun (owner)
POST   /api/auth/change-password    # ganti password sendiri + token baru
POST   /api/auth/bootstrap          # seed akun dari perangkat utama (kunci admin)
POST   /api/auth/recover            # reset owner dengan kunci admin
```

`/api/auth/forgot-password` dan `/api/auth/reset-password` sekarang menyimpan
password baru langsung di `casa_users`, sehingga berlaku di semua perangkat.

### 2. Token login untuk endpoint terproteksi

- Token ditandatangani HMAC (`AUTH_TOKEN_SECRET`, fallback ke
  `CATALOG_ADMIN_KEY`).
- Endpoint terproteksi menerima `Authorization: Bearer <token>` atau header
  lama `x-admin-key`.
- Setiap request token memeriksa status `active` dan fingerprint password.
  Menonaktifkan akun atau mengganti password langsung membatalkan token lama.
- Kunci admin tetap berfungsi sebagai jalur kompatibilitas/pemulihan.

### 3. Sinkronisasi otomatis setelah login

- `src/services/sync.js` memakai token login lebih dulu, lalu kunci admin.
- Login pertama di perangkat baru selalu **menarik state server** dan tidak
  pernah menimpa server dengan state seed kosong.
- Penanda `casa-ramire:sync` menyimpan versi server terakhir yang sudah
  disinkronkan perangkat.

### 4. Audit editor terakhir

`store.update()` sekarang menyimpan `meta.updatedBy`
(`id`, `name`, `username`, `role`) dan dashboard/Pengaturan menampilkan
"Terakhir diubah oleh ...".

### 5. UI

- Badge sinkronisasi di topbar: `Tersinkron`, `Menyinkronkan…`, atau
  `Sinkron nonaktif`.
- Manajemen Akun memakai endpoint server dan menampilkan status sinkron.
- Petunjuk Kunci admin diperbarui: hanya untuk perangkat utama/pemulihan.

## Migrasi satu kali setelah deploy

1. Deploy kode ini (Vercel otomatis dari `main`).
2. Buka/reload aplikasi di **perangkat utama owner** (perangkat yang selama ini
   sudah tersinkron dan memiliki Kunci admin di Pengaturan).
3. Tunggu beberapa detik. Aplikasi otomatis memanggil `/api/auth/bootstrap`
   dan membuat tabel `casa_users` dari akun lokal perangkat tersebut.
   Akan muncul toast: `Akun server disiapkan (...)`.
4. Logout lalu login kembali di perangkat utama (opsional, untuk mendapatkan
   token login).
5. Di laptop/HP/tablet lain: cukup login dengan username & password yang sama.
   Data akan ditarik otomatis; tidak perlu Kunci admin.

Jika akun server belum siap, login di perangkat baru akan menampilkan pesan
`Akun belum disiapkan di server...` dan memakai akun lokal sementara.

## Environment

```text
CATALOG_ADMIN_KEY    # wajib, sudah ada
AUTH_TOKEN_SECRET    # opsional; jika kosong memakai CATALOG_ADMIN_KEY
POSTGRES_URL / POSTGRES_URL_NON_POOLING  # wajib, sudah ada
```

Mengganti `AUTH_TOKEN_SECRET` membatalkan semua token login.

## Invoice PDF & email otomatis

Ditambahkan setelah login lintas perangkat:

- Generator invoice PDF di server (`api/_lib/invoice.js`, `pdf-lib`):
  - header hijau + logo Casa Ramire,
  - data klien (nama, alamat, telepon),
  - item, periode, total, tanggal, dan nomor order,
  - badge LUNAS dan info transfer untuk invoice belum dibayar.
- Endpoint `GET/POST /api/invoice`:
  - `GET ?type=bill|invoice|pos&id=...` → PDF,
  - `POST { type, id, mode, to }` → kirim PDF + email.
- Preview invoice di aplikasi (`src/services/invoice.js`) dengan tombol
  Download PDF, Cetak, dan Kirim Email.
- Tombol **Tampilkan Invoice** ada di tagihan sewa, invoice manual, dan POS.
- Setelah verifikasi pembayaran, email ucapan terima kasih + PDF dikirim
  otomatis; untuk POS langsung bayar, email dikirim saat transaksi disimpan
  jika email pelanggan tersedia.
- Cron pengingat diubah dari H-7 menjadi **H-3** dan sekarang melampirkan PDF.
- Draft teks email ada di `docs/INVOICE-EMAIL-DRAFTS.md`.

## Rollback

Kode lama tetap bisa memakai `x-admin-key`; tabel `casa_users` tidak
mengganggu. Jika perlu rollback frontend, sinkronisasi perangkat utama tetap
berjalan dengan kunci admin.
